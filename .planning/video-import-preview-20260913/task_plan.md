# 视频批量导入确认 Implementation Plan

用户已指定“像软件一样，先在窗口统一识别确认再入库”。沿用该方向完成实现，不另起代理、不改动用户正在整理的真实目录；原有未提交修改全部保留。应用 brainstorming / writing-plans / systematic-debugging / 行为回归方法，主会话执行与审查，不提交。

## 设计

- 扫描本地、导入目录与设置页的影视扫描统一进入“视频导入确认”窗口。先做本地识别；完整项默认选中，资料不足项可编辑或显式 Agent 复查。单条已入库作品的重新识别仍是独立操作。
- 每批有持久 ID、独立进度、稳定行 ID、选择与编辑信息。确认窗口不使用普通重新识别的全局扫描结果/进度，单行复查不会替换整批；关闭窗口后从“导入确认”入口继续。
- 后端在内存数据库快照里复用扫描/登记逻辑，捕获经过校验的登记命令。预览及复查只保存草稿与日志，不写正式作品、合集、媒体文件或侧车资料。
- 确认时后端重新校验文件事实与正式影视库版本，在事务内重放所选项的登记命令和用户编辑，保留未选项。重复确认不重复登记；中途移动文件、资料变更或归属冲突会保留草稿并给出重查入口。
- 已确认行保留状态与正式资源 ID。草稿可主动丢弃，不移除正式资源或视频。隐私隐藏时关闭预览并屏蔽批次信息。

## 验证重点

1. 三个本地候选预览后正式 resource/episode/assets/目录清单均不变；完整与不足资料分类正确，不调用 Agent。
2. 只确认一个候选，库中只出现那个资源，其他两行、选择与标题保持；重复确认无新增。
3. 复查一行后仍保留原批次 ID 和另两行的名称/状态，日志与消耗仅归属该行。
4. 失败或取消复查不清空旧提案；重启后可恢复未确认批次。
5. 确认前移动或更改视频、覆盖 info、变更正式作品资料均阻止过期写入，保留全部已有记录。
6. 已存在逻辑合集、主动移除与多作品共享目录场景，不绕过既有归属保护。
7. 首页/设置页统一窗口、键盘关闭、窄屏可操作；旧结果区域不再被单项任务进度驱动。
