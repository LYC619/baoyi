# 单集直链下载设计

## 范围和授权
沿用已确认顺序：任务中心 → 单集下载 → 系列队列。用户授权直接实施、不逐项询问、不用子 agent。本阶段只做单集；不改海报、不自动注册或替换本地影片、不打包、不运行或关闭应用、不提交现有 dirty 工作区。

## 参考和方案
本地 Han1meViewer 的 logic/Parser.kt:546-569 读取 video#player 的 source/size/type，缺失时在 #player-div-wrapper script 提取 const source。选择原生 fetch + 文件流，而非 Electron 全局 DownloadItem 事件或新下载框架，便于离线测试和后续队列复用。复用已有 Hanime session.fetch 的代理/验证会话，不手动复制 Cookie。

## 交互和授权
- 有 hanime_id 的详情页提供单集下载区。点击解析才联网，显示站点实际单集标题、编号和清晰度，默认最高。不推测本地 Episode 和站点编号的对应关系。
- 选择清晰度后“另存为并下载”，路径只由主进程原生保存对话框提供。默认系统 Downloads，之后记住本次运行目录。文件名含编号/清晰度，清理 Windows 非法字符和设备名。
- 主进程保管短期源令牌；renderer 只发送资源 id、源令牌、请求 id，不能指定 URL、headers 或目标路径。开始时重新确认资源与站点编号；过期源要求重新解析。
- 同时一个单集传输（含选路径），不与扫描共用锁。跨页面保留状态和订阅直到 Promise 收尾。取消入口放下载模块，等待实际收尾再结束任务。
- 全局任务中心显示字节、速度、阶段、错误和结果路径。完成可打开文件位置；不改数据库、已有路径、海报或观看状态。

## 完整性与错误
- 同目录独占随机 .baoyi-part 文件，背压流写入；检查 HTTP、容器头、非空、已知 Content-Length，拒收挑战 HTML/JSON、部分响应及 HLS/DASH 清单。
- 限制重定向次数/协议和无进展超时；带 UA/Referer，不记录 URL 签名、Cookie 或授权信息。
- sync/close 后 hard-link + unlink 原子且不可覆盖发布；同名竞争也不能覆盖。不支持硬链接的文件系统明确失败，建议换 NTFS，不降级成会暴露半成品的复制。
- 取消/失败只删自己创建的临时文件；清理失败报告路径。发布成功后晚到取消不改变成功。异常退出可能遗留命名明确的临时文件，不清理未知文件。
- 阶段、进度里程碑、错误和最终摘要进入任务面板/控制台。任务不持久化；断点续传、重启恢复、磁盘日志系统、自动重试、分片合并和系列队列不在本次范围。

## 验证和自审
先失败测试再实现：源解析/过滤/排序；正常和未知大小、重定向、HTTP、断流、空内容、长度错误、挑战页、HLS、取消、超时、磁盘错误、同名竞争和清理；令牌/IPC 边界；renderer 收尾、跨组件共享、事件隔离、取消竞争。最后跑旧回归、类型检查和生产构建。没有改变扫描识别流程，也不承诺实站或 GUI 已验证。
