# 项目类与移动项目

用户已确认项目类定位、四个试点，并于 2026-10-06 授权开工，追加移动项目功能。本轮实现完整可用的项目管理入口；文档与个人档案作为后续品类。

## 范围
- 项目导入支持单项目目录、混合目录发现及文件条目，候选可改名、改分类、来源、排除或合并为一个关联项目。
- 项目支持名称、简介、分类、来源、状态、分组、标签、置顶、备注、多个文件/目录/网址/Obsidian/外部工具入口，用户设置默认打开项。
- 列表及详情沿用现有抱一主题、侧栏、卡片和模块切换记忆；主进程负责文件和数据库操作。
- 扫描采用本地规则，读取有界 README/项目目录说明/包元数据；不执行脚本，不把 Git 当作软件用途的充分条件，不读取凭据文件。AI 识别不作为首版前置条件。
- 项目与软件等既有资源通过关联项连接；项目根不重复占用其他品类已经登记的根路径，冲突时显示说明。
- 增加 schema v14，项目元数据纳入备份、恢复、重置及升级快照流程。

## 移动
- 用户选择目标父目录和新名称，预览主目录/主文件的物理移动及所有抱一已登记路径的更新。
- 外部参考目录保持位置，界面列出数量；合并项目的多个位置仍以明确的主目录为物理移动范围。
- 目标不得存在，不覆盖；拒绝卷根、受保护程序/数据目录、源的子目录、符号链接主根和有外部 Git 管理位置的工作树。
- 默认允许目录移动后保留旧位置入口（junction），使旧笔记和脚本路径继续可用；可取消并提示外部绝对路径需要自行修正。不改写源码或 Obsidian 正文。
- 同卷重命名；跨卷先复制到唯一暂存目录，核对完整文件摘要及源未变，才启用新位置。失败保留可恢复数据；原目录仅在提交成功后送回收站。
- 移动过程互斥，预览有期限，执行前重新校验。数据库原子更新；磁盘/数据库不一致时保留持久恢复记录，重启后可核对并完成恢复。
- 已使用中的项目应先关闭相关外部工具。程序无法证明所有外部进程闲置，需明确此边界；系统拒绝文件操作时报告实际错误。
