# 运行期全局任务中心设计

**日期：** 2026-09-05

## 背景

抱一当前的扫描、AI 识别、游戏扫描、影视扫描、整理和内置 Cloudflare 验证分别在页面或 composable 内维护状态。切换页面后，用户只能看到当前页面的局部提示；任务失败原因也可能只存在于一次 toast 中。应用通常按一个 agent 一个软件逐条注册，因此本阶段不需要重启恢复或持久化队列，但需要一个跨路由的运行期状态和日志入口。

## 目标

1. 在标题栏提供全局任务入口，显示运行中的任务数量和失败提醒。
2. 点击入口后查看当前任务、进度、当前对象、最近日志和最终结果。
3. 页面切换不丢失运行期状态；任务结束后保留最近的任务历史。
4. 统一记录开始、进度、成功、失败、取消和部分成功信息。
5. 复用现有 IPC 进度事件和业务逻辑，不把任务状态迁移到数据库。
6. 为后续单集下载和系列下载复用任务展示与日志模型。

## 非目标

- 不在本阶段实现任务数据库、重启恢复或断点续跑。
- 不修改现有 `identify_logs` 的资源级数据结构。
- 不改变各模块当前的扫描、识别、整理业务算法。
- 不实现媒体下载。
- 不强制移除各页面已有的局部进度条。

## 用户体验

标题栏右侧增加一个任务按钮，位于模块导航和窗口控制按钮之间。按钮是可拖拽区域中的非拖拽控件：

- 无任务时显示任务图标；
- 有运行中任务时显示运行数量和动态状态色；
- 有失败任务时显示失败数量和警示色；
- 任务面板打开时，列出运行中任务和最近结束的任务。

任务面板包含：

- 任务标题、类型和状态；
- 进度条和 `processed / total`；扫描阶段总数未知时显示不确定进度；
- 当前路径、条目名或 agent 最近动作；
- 开始时间、结束时间和结果摘要；
- 每个任务的最近事件列表；
- 清除已完成历史的按钮。

任务面板不会提供“强制终止”按钮。能够取消的任务继续使用各自已有的取消入口，任务中心只反映取消状态，避免产生一个看似可以取消但没有对应 IPC 的全局按钮。

## 状态模型

任务类型：

- `software-scan`
- `game-scan`
- `video-scan`
- `ai-identify`
- `organize`
- `hanime-verify`

任务状态：

- `running`
- `success`
- `failed`
- `cancelled`

每条运行期任务包含稳定 id、类型、标题、开始和结束时间、处理计数、总数、当前对象、当前消息、最终摘要和事件数组。历史保留最近 30 条任务；单条任务事件最多保留 100 条。任务记录只保存在渲染进程模块级单例中，窗口关闭后释放。

## 架构

新增 `src/composables/useTaskCenter.ts` 作为模块级单例。它不执行任务，只提供：

- `start()` 创建运行中任务；
- `update()` 更新进度和当前消息；
- `finish()` 记录成功、失败或取消；
- `clearFinished()` 清理历史；
- 只读 computed：当前任务、历史任务、运行数量、失败数量。

新增 `src/components/tasks/TaskCenter.vue` 负责标题栏入口和详情面板。`TitleBar.vue` 只负责挂载它，不保存任务状态。

以下入口在调用已有 IPC 前后接入任务中心：

- `useScan.ts`：软件目录扫描；
- `useAI.ts`：软件 AI 识别；
- `game/Home.vue`：游戏扫描；
- `video/Home.vue`：影视扫描；
- `useOrganize.ts`：软件整理；
- `Settings.vue`：Cloudflare 验证。

已有的进度订阅仍保留给页面自身使用，但同一进度事件同时更新任务中心。所有结束路径都在 `try/catch/finally` 中明确写入结果，不能让任务永远停留在 `running`。

## 日志策略

每个任务写入统一格式的会话事件：

- 开始：任务开始；
- 进度：处理数量、当前对象或 agent 动作变化；
- 警告：降级、部分失败、用户取消；
- 成功：完成摘要；
- 错误：异常消息和可读失败原因。

事件直接显示在任务面板中，并使用 `[task:<kind>]` 前缀输出到开发控制台。资源级识别细节仍由 `identify_logs` 管理，任务日志不写入数据库。

## 错误语义

- 正常完成且没有失败项：`success`；
- 调用抛出异常：`failed`，保留异常文本；
- 用户主动停止：`cancelled`，保留已完成数量；
- 扫描完成但存在失败项：任务仍为 `success`，摘要标明失败数量；这表示任务流程完成，而不是所有条目成功。

## 测试

新增 `scripts/verify-task-center.ts`，不启动 Electron，使用真实的任务中心模块和 Vue 响应式，覆盖：

1. 创建任务、更新进度和完成摘要；
2. 成功、失败、取消三种结束状态；
3. 事件追加、同一消息去重和事件上限；
4. 最近任务上限淘汰；
5. 清除已完成历史而保留运行中任务；
6. 多个任务并存时运行和失败计数；
7. 延迟的旧任务更新不会改变已结束任务；
8. 构建、现有设置扫描回归、Cloudflare 生命周期回归、海报回归和项目自检继续通过。

## 取舍

采用渲染进程内存任务中心，而不是主进程事件总线或数据库任务表。这样能覆盖本轮用户体验问题，改动集中、无迁移风险，并且后续下载功能可以复用展示模型；下载的持久化队列和恢复机制另行设计。

## 实现补充（2026-09-05）

- 游戏与影视扫描从页面内订阅改为共享 useMediaScan；任务拥有 IPC 订阅，路由卸载不释放正在运行的订阅，Promise 收尾后统一释放。详情页重新识别共享影视通道互斥，避免进度、取消对象串线。
- 软件扫描的停止标志也采用模块级共享状态。取消只发一次；设置页从其他页面观察或发起停止时，仍按当前任务的真实停止结果显示，不将其误报为绿色成功。
- 扫描预检没有运行任务时不可停止，失败后的新一轮不沿用旧进度开放停止入口。同意降级识别后的原因写入本轮 warning 日志。
- 面板最近事件有上限，但所有新增事件同步输出带任务类型前缀的控制台日志；相邻同级同文本事件去重。任务日志没有新增文件/数据库持久化，关闭或重载渲染进程后任务面板记录消失，原有 identify_logs 不受影响。
- 额外提供 verify-task-operations 与 verify-task-center-ui 两个离线回归入口，不启动 Electron 或网络请求。实机点击、窗口拖拽、高 DPI 和实时 Cloudflare 验证不在本轮离线验收范围。
