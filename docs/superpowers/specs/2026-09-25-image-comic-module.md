# 图片与漫画模块方案（2026-09-25）

## 目标与已确定的范围

在现有 Electron + Vue + SQLite 架构中增加一个「图片」品类。首版同时支持本地相册和本地漫画：照片以文件夹／相册为一张资源卡，漫画以作品为一张资源卡，作品下有章节和页。漫画提供预设类型、用户新增类型和可多选标签。核心浏览、阅读、进度和搜索均可离线使用；联网仅用于用户主动选择的下载来源。首版接入哔咔，完成登录、搜索、选章、下载、入库。

不把图片逻辑并进 `video`：共用资源总表、分类／标签、任务中心、导入确认、文件操作与安全协议的模式，但图片的章节、页、阅读进度和下载来源由新模块维护。也不另起一个独立阅读器应用，以免出现第二套库和设置。

## 信息架构

- 顶栏新增「图片」。图片首页顶层切换「照片」「漫画」；照片区以相册卡片呈现，并保留统一搜索、导入、扫描、下载记录入口。
- 相册卡片对应一个文件夹；打开后是缩略图网格和灯箱，支持键盘翻图、适屏／原始尺寸、旋转与排序。相册可按来源目录和标签筛选。
- 漫画卡片对应一部作品；进入详情看到简介、封面、类型、标签、章节、最近阅读位置和下载状态。漫画侧栏的类型先给少量预设（如日漫、韩漫、欧美漫画、其他），可新增、重命名、排序；题材和作者等交给多选标签。
- 阅读器首版提供单页左到右／右到左、双页、纵向连续三类模式，适屏／适宽缩放、全屏、键盘／点击翻页、章节切换与自动保存进度。照片灯箱不带章节进度。
- 若漫画类型中出现需要隐藏的分组，沿用影视模块的“隐藏后不泄露卡片、搜索结果和计数”原则，但配置与筛选属于图片模块，不绑定影视开关。

视觉上沿用抱一现有的深色主题（背景 `#1E1E2E`、侧栏 `#181825`、卡片 `#2A2A3C`、强调色 `#7C6AF6`）、200px 左侧栏和克制的工具感。漫画封面按纵向比例、相册封面按横向比例；阅读器让图片占据中心，仅在指针移动或键盘操作时显示工具栏。图片内容本身是视觉焦点，界面不使用抢眼的渐变、玻璃拟态或装饰插画。

## 数据与本地文件边界

- `resource.kind = 'image'`，一条 `resource` 代表一个相册或一部漫画；`resource.path` 是相册目录、漫画目录或单本 CBZ 的路径。`resource.category` 仅表达顶层「照片／漫画」，避免把章节或单张照片塞进资源总表。
- 图片私有表存 `item_type`、封面、来源、扫描状态；漫画类型用独立的分组表和 `group_id`，这样预设和自定义类型都可维护，也不会与相册分类混淆。沿用公共 `tags` 和资源标签。
- 页面索引只保存文件定位、顺序、尺寸及状态；漫画另有章节表和阅读位置表（作品、章节、页）。相册页面的章节为空。在线来源保存 provider + 站方作品／章节 ID，不用标题当唯一身份。
- 本地导入默认建立索引，不移动或改名原文件。下载内容写入用户选定的本地目录，先暂存、校验，再原子落盘并登记数据库；失败时保留可重试状态。重扫按稳定路径或来源 ID 更新，保留人工改过的名称、类型和标签。
- 首版读目录图片及 ZIP／CBZ；CBZ 内条目需限制解压总量、单页尺寸和条目数量，拒绝绝对路径与 `..`。RAR／7Z、PDF、EPUB 作为后续独立格式任务，不让格式矩阵拖慢首版闭环。
- 缩略图和阅读页通过主进程受限读取／缓存协议提供，不把任意磁盘路径交给渲染进程；原文件丢失时显示“重新定位”，不静默删除资源。

## 哔咔来源闭环

1. 来源适配器只负责认证、搜索、作品详情、章节清单和逐页下载；业务层接收统一的 `source / work / chapter / page` 形状。库与阅读器不依赖站点响应格式。
2. 登录信息不进入普通设置、任务日志或截图。用户可主动登录／退出；网络失败、认证过期和站点结构变化只影响在线操作。
3. 搜索结果先进入详情预览；用户勾选章节、选择落盘目录和是否补齐已有章节后才创建任务。任务中心显示章节／页进度、失败原因、取消与仅重试缺失页。
4. 下载完成后使用与本地扫描相同的登记流程；同一站方章节重复下载不生成第二部作品，已落盘页不因重试被覆盖。封面和章节顺序可人工修正。
5. 使用本地模拟服务验证来源适配器、认证过期、限速、断点重试和错误响应；真实账号仅用于隔离资料库中的手工冒烟检查。

## 实施顺序与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| 1. 数据地基 | 注册 `image` 品类、私有表与迁移、相册／漫画两级分类和安全文件定位 | 旧库升级不改影视数据；相册、漫画和章节身份稳定 |
| 2. 本地导入 | 根目录扫描、导入预览与确认、目录图片及 CBZ 索引、封面／缩略图 | 不移动原件；重复扫描不重复入库；坏文件只影响对应条目 |
| 3. 书架与阅读 | 相册网格／灯箱、漫画书架／详情／阅读器、标签、类型与进度 | 断网可读；重启恢复到同一章节同一页；大图和长章节不卡死 |
| 4. 哔咔来源 | 登录、搜索、选章、下载、任务中心、自动登记 | 下载中断后仅补缺失页；无重复作品；在线故障不阻断本地库 |
| 5. 交付回归 | 合成目录与 CBZ、异常归档、迁移、打包 UI 和独立资料库排练 | 类型检查、自检、离线集成和打包应用检查通过 |

首版不承诺跨设备同步、在线漫画浏览器、OCR、相册人脸识别、全格式解压或自动修改用户原目录。这些都可以在上述闭环稳定后单独评估。

## 预计接入位置

- `electron/kinds/image/`：schema、分类、扫描、索引、阅读定位、来源适配器与下载任务。
- `electron/kinds/index.ts`、`electron/services/schema.ts`：品类注册与库迁移。
- `electron/main.ts`、`electron/preload.ts`、`electron/ipc/`：受限图片协议和明确的 IPC 能力。
- `src/router/index.ts`、`src/composables/useModules.ts`、`src/components/TitleBar.vue`：图片入口及路由状态。
- `src/pages/image/`、`src/components/image/`、`src/stores/image.ts`：书架、相册、漫画详情与阅读器。
- `scripts/verify-image-*.ts`：合成资料、下载模拟和打包验证。

在动工前，对现有未提交的影视改动先形成可复现基线；图片模块按阶段独立提交，避免迁移与尚未收尾的影视变更混在一起。
