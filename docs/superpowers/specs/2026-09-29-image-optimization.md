# 图片工作流优化设计

用户已同意按优先级逐项完成，并要求建立持续目标。本设计沿用现有 Electron / Vue / SQLite 架构，不新开子代理。

## 分阶段边界

1. 下载状态与进度：先列出所选章节的页面清单，再下载正文。整部总页数确定后不变；同时记录当前章、校验复用页、已存文件字节数、本次接收字节数和滚动速度。来源适配器发出不含 URL/令牌的连接、接收、重试、限流事件。等待期间不伪造速度和剩余时间。
2. 下载控制：明确 paused 状态；暂停不删已写入文件，继续验证后只补缺页；串行作品队列可排序，页级有限并发，遇 429 降为串行并尊重退避。多个 worker 的写盘和清单更新必须集中协调，避免丢记录。
3. 完整性：保留原始格式和字节；读取尺寸/格式/大小用于展示。只读审计清单与磁盘，汇总正常、缺失、损坏；修复只处理异常页，保留正常页与手改资料。
4. 更新：仅用户触发远端章节检查；按 sourceId 与本地清单对照，明确新增/已下载/不完整；选择新增章节加入原下载目录。远端更新不覆盖本地修改。
5. 阅读：适配现有单页/双页/连续模式，缩放和拖动不改变文件；封面单页规则、作品级偏好覆盖全局默认；书签与阅读进度独立，已读状态与来源完结状态独立。
6. 管理与性能：批量分类、标签、已读操作使用事务与现有权限/隐藏规则；先用合成大书库测加载和图片解码，再做有证据的优化，不直接引入新 UI 框架。
7. 升级安全：在任何数据库升级写入前做一致性快照；记录版本与备份元数据，备份失败不能无提示继续破坏性升级；明确实际数据路径，保留手动备份恢复入口。

每阶段先完成代码、局部回归和主会话审查，后续阶段再展开详细计划。
最终版本拟为 0.10.0；当前 0.9.0 及用户正在运行的旧验证包完整保留。

## 第一阶段数据约定

`ImageDownloadJob.progress` 为兼容旧任务的可选字段，载入时规范化。
包含 `phase`、`totalKnown`、`catalogChapters`、`chapterIndex`、`chapterProcessed`、`chapterTotal`、
`reusedPages`、`storedBytes`、`receivedBytes`、`bytesPerSecond`、`retryAt`。

- `processed/total`：本轮已确认完整的页数 / 所选章节的真实总页数，已存在且通过校验的页面也计入完成。
- `storedBytes`：本轮已确认的文件总字节数，包括复用页；`receivedBytes`：本轮实际接收的图片数据，包含失败重试已收到的部分。
- `bytesPerSecond`：短时间窗口测量，连接/退避/终态归零，不按已复用文件大小估计网络速度。
- `retryAt`：等待截止时间，非重试状态清零；任务记录和 UI 不保存凭据或请求 URL。
- 字节流事件只更新内存并限频通知；章/页完成和终态落库，避免每个网络分块都写 SQLite。
- 总目录未确认时显示不定进度，不把来源整部页数当成用户所选章节页数。

## 验收

覆盖多章固定分母、字节流、重试/限流/取消、复用页不算网络流量、旧任务载入与终态速度归零。
保留现有图片来源、下载、资料库和 Chromium 网络回归；UI 用独立合成数据验证长标题、窄窗口、状态和数值。
