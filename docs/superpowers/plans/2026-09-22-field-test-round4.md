# 影视库实测第四轮 · 计划与决定（2026-09-22）

用户 9-21 晚实测「统一移动」出的问题，加四条界面调整。交付说明在
`docs/changes/2026-09-22-video-field-test-round4.md`。

## 问题定位

**统一移动把文件夹和配置搬走了、视频留在原地。** 用户库里那部作品（`944c2c34…`）的整理日志
和 `library-layout/` 记录把过程还原得很清楚：

1. 第一次移动时作品还没绑定目录，走「搬文件」路。目录名按 `safeWorkFolderName` 截到 90 字，
   文件名（232 字）没截，拼起来 261 字超过 `checkDestination` 的 240 字上限 → mp4 和 png 被判
   `unsafe-path`，只有 info.json 和 .nomedia 搬成功。
2. `runOrganize` 只要有一个文件成功就 `bindOrganizedDirectory` + `syncManifest`：作品被绑到新目录、
   `resource.path` 切过去，日志停在 `partial`。
3. 改短名字再移动：作品已经有绑定目录 → 走「整目录改名」路。它只改名 + `rebaseMovedVideoDirectory`
   目录**里面**的路径，目录外的视频一个没碰，如实报「已移动整个作品目录」。
4. 那条 `partial` 日志记的目标是已经消失的长目录：重试撞「作品已绑定另一目录」，回退找不到目标文件，
   还会挡住这部作品之后所有整理（`makeJournal` 的未完成检查）。真库里 `新 最終痴漢電車 1-3` 也在
   同一个坑里（9-21 被统一移动改名过）。

## 改法

- `organize.ts`
  - `fitFileName`：目标文件名装不下 240 字时按目录同样规矩截短（留扩展名、补 8 位哈希）。
  - `healJournal`：读日志时，绑定了目录、状态 partial/running、旧目标目录不存在、当前绑定目录存在且
    清单 UUID 一致 → 整本日志路径对齐到新目录；没搬成的文件若是路径过长顺手截短并撤掉对应冲突；
    把当前清单当基线（改名时已被 `persistVideoWorkBundle` 重写，否则 `syncManifest` 会拒绝）。
    在 `listVideoOrganizeJournal` / retry / rollback 都过一遍。
  - `pendingVideoOrganize`：把 `makeJournal` 的「会挡住新整理」判断抽出来给统一移动用。
- `layout.ts`
  - 「搬文件」预览：视频文件有 file 级冲突 → 整部作品标 skip，不再搬两个配置文件就绑目录。
  - 绑定了目录但视频在目录外（就是用户现在的状态）：已就位 → 走「收进来」；要改名 → 改名后再收。
    有未完成日志且目标就是这个目录 → 重试那条日志，而不是另起一次。
  - 有未完成日志的作品不做整目录改名（先在整理记录里处理）。
- 界面
  1. 顶部「任务」改成「日志」，四个页签：任务 / 下载记录 / 整理记录 / 识别与调用。红色角标
     = 下载待处理 + 任务失败，鼠标悬停有拆分；「下载记录」默认只看待处理。
  2. 「从链接添加」+「打开 Hanime」合并成一个「从 Hanime 添加」；面板里的「在 Hanime 里找」开站内窗口。
  3. 工具栏去掉「导入确认」；有待确认项时副菜单栏出现「导入待确认 N」，设置页入口保留。
  4. 副菜单栏和详情页「更多」里的「整理记录」删掉（详情页「文件与资料」里的保留，那是单部作品的）。

## 决定

- `applyLogical` 只在「合并多部 / 整理出多集 / 明确建合集」时把作品改成剧集（Codex 审查 P1）。以前只要有一集就改，
  电影也有一条兼容集，所以单部电影走统一移动（搬散文件、收目录外视频）会被改成剧集；第三轮的「搬文件」路就已经有这个问题。
- 设置页的「识别日志」页签保留；「最近调用日志」抽成 `SearchCallLog` 组件，从设置页挪进日志面板。
- 没有 pending 日志的「散文件」作品和第三轮一样走整理流程；有 pending 的先让用户在整理记录里处理。
