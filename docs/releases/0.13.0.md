# 0.13.0 · 项目库与项目移动

2026-10-06。新增第五个品类「项目」，用于掌握项目的位置、用途、来源、状态和常用入口。写作、开发和资料编辑继续在 Obsidian、Office、编辑器等外部软件中完成。

## 项目库

- 支持导入一个目录、从混合目录发现候选，以及从单个文稿、脚本或程序建立项目。候选可改名、分类、标记来源、排除、合并，或加入已有项目。
- 支持软件项目、调研写作、资料处理、个人事项和其他类型；来源、状态、分组、标签、置顶、备注与默认入口均可手动调整。
- 入口支持文件、目录、网页、Obsidian 笔记、EXE 与逐项参数，以及已有软件、游戏、影视或图片资源。资源选择遵守已有隐藏设置。
- 刷新入口候选时保留手动字段；位置失效后可重新定位。路径名称含点号的目录也可重新定位。
- 列表支持搜索、来源与状态过滤、排序、模块切换记忆及深浅色主题。

## 移动项目

选择目标父目录和新名称，预览后移动主目录或主文件，统一更新抱一登记的内部路径与启动参数。项目关联在其他位置的参考资料仍留在原位置。多个位置合并为一个项目时，界面显示的主位置就是物理移动范围。

目录默认在旧位置保留 junction 入口，帮助原有绝对路径继续访问。同盘目录使用重命名；跨盘先复制到暂存位置、核验文件摘要及源未变化，再更新资料库，最后将旧副本送入回收站。单文件使用排他复制避免覆盖竞争目标。失败副本和持久移动记录供核对恢复，恢复时不自动删除文件。

移动拒绝同名覆盖、磁盘根目录、自身子目录、链接主根、当前程序或资料库目录，以及关联外部工作树的 Git 项目。移动前需关闭相关编辑器、程序和同步任务。若要移动抱一自身的源码目录，先把整个运行包放在该目录之外再启动。

旧入口只适用于目录。取消旧入口后，源代码、笔记正文、快捷方式和目录链接里的旧绝对路径需要自行调整；抱一不会重写这些内容。复制后源又有变化、回收失败或旧入口建立失败时，会显示警告并保留可核对的数据。首版使用本地规则识别，没有自动执行项目脚本。

## 数据与验证

数据库升级为 schema v14，项目元数据加入全库备份、恢复与重置；兼容导入没有项目数据的 v13 备份。移动恢复日志在数据目录的 `project-moves/`，不随 JSON 元数据备份迁移。

四个真实试点只作读取扫描，未移动原件。移动、回退与界面验证使用临时项目和独立资料库；包含真实 C 盘到 D 盘移动、目录 junction、单文件、过期预览、源身份变化、复制中断和目标内容变化。外部打开在界面测试中验证请求参数，不执行扫描发现的脚本。

最终验收与源码摘要保存在 `release/0.13.0/verification.json` 和 `manifest.json`；详细证据见 `output/project-verification/`。本次交付标准目录版，运行 `release/0.13.0/win-unpacked/抱一.exe` 前正常退出旧版，并保留整个 `win-unpacked` 目录。0.12.1 原位保留。
