修复包：[抱一.exe](D:/8.Project/0_0_维护/抱一/release/0.8.0-video-agent-grouping-20260913/win-unpacked/抱一.exe)。退出旧版后运行，保留整个 `win-unpacked` 文件夹。

## 这次报错的含义

`Agent 没有提交可用分组` 表示分析结束时，程序没有收到通过校验的分组预览。错误发生在确认执行之前，没有合并作品或移动视频。

原任务选择了 137 部作品，约 23 秒后失败。旧版日志只记下开始和失败，未保存模型答复、工具校验错误与停止原因，因此无法还原这一轮模型的具体返回。已确认的程序问题是：一次发送全部作品，任意一组不合格会丢弃整次提交，成功提交后还会额外请求一轮总结。

用户配置的 MiniMaxAI/MiniMax-M3 在两个中性虚构条目上能够调用分组工具。新请求格式也已用同样的中性样例验证：1 次请求、1 个有效分组、706 tokens。没有发送真实片名、视频路径或本地文件。

## 修复后的行为

- 先从本地片名和集数找同系列单集候选，再按每批最多 24 项交给模型核对。已有多集合集不参与单集合并，但仍可补封面或资料。
- 同系列尽量放在同一批。超过 24 集时，每批带一个共同参照集；只有模型明确认可的重叠分组才合成同一个预览。
- 每组独立校验。范围外作品、重复归组、不同系列或重复集数仍不能合并；有效分组保留，无效分组显示具体原因。
- 整理请求明确要求工具提交，成功后立即停止。完整 JSON 或 JSON 代码块也可接收，但必须通过相同校验；普通说明文字不会自动转成合并操作。
- 失败原因会回传给模型用于修正，并保存到预览日志和任务日志。模型回复、提交参数、校验错误、结束原因及 token 数都能查看，失败任务重启后仍保留诊断信息。
- 界面区分没有候选、模型未建议合并、部分建议失败及分组分析失败。可直接重新生成预览；分组失败时仍可确认所选的补封面、补资料操作。
- 继续在用户确认后才更改资料库和文件。已有的观看进度、单集资料、移动撤销及过期预览保护保留。
- 批量执行中，首页刷新产生的文件检查时间不再让后续分组误判为过期。实际文件、路径、资产状态或资料变化仍要求重新预览。

综合自检还发现并修正了一个之前遗留的问题：没有合集级 NFO 时，第一集简介会被用作整个合集的简介。现在多集作品的简介不会这样回填，单集自己的简介仍保留。
