## 问题出在哪

### 一、继续阅读（已修，定位明确）

`src/pages/image/Home.vue` 里那个区块的显示条件只有两条：有阅读进度、当前是漫画。没管分类。
分类、标签、搜索、收藏走的是同一个 `store.query`，所以切到分类它照旧占一排。

修法：加一个 `atHome` 判定，只有落在默认视图（没选分类、没搜索、没标签、没收藏筛选、没已读筛选）时才显示。

### 二、哔咔界面标注已入库（已修，定位明确）

本地库一直知道哪些作品来自哔咔：`image_meta` 表里的 `source='pica'` 加 `source_id`，
批量下载跳过重复作品用的就是这两个字段。只是界面从来没去问过。

新增一个只读查询 `image:source-owned`，一次回答三件事：哪些作品已入库、哪些正在下载、已入库的作品本地已有哪几章。
界面上的变化：

- 列表里给作品挂「已入库／下载中」徽标。
- **已入库的作品不能再被批量勾选**（避免重复下一整遍）；「全选当前页」也自动跳过它们。
- 作品详情页里逐章标「已入库」，方便判断该补哪几章。
- 标注取不到时只是不显示徽标，不挡浏览、不挡下载。

### 三、弹窗全屏被顶栏压住（已修，定位明确）

`src/components/image/ImageReader.vue` 里，阅读器的「最大化」**是故意**留出 38 像素顶栏实现的
（样式写的是 `inset:var(--titlebar-h)`），所以看起来像个假全屏。改成铺满整个窗口。

代价说清楚：最大化期间应用顶栏被盖住，窗口的最小化／关闭按钮看不见了。阅读器自己右上角有收起、还原、关闭三个按钮。
另外按 F 或点「全屏阅读」走的是系统全屏（连任务栏一起盖住），那条路径一直是铺满的，没动。

### 四、打开所在文件夹（新增）

照影视、软件、游戏三个模块同一个写法：主进程按 id 从库里取路径，是目录就打开目录，
是归档（zip／cbz）就在资源管理器里选中它。路径只从库里按 id 取，渲染层递不进任意路径。

位置在图片详情页「作品工具」那一行。

### 五、输入框有时候失灵（没复现，做的是有依据的缓解）

你描述的是：有时候操作完输入框点得进去但打不了字，切出去一会儿再回来就好了，有时要重开。

**这条没有复现。** 但症状本身就是一条线索：点得进去、打不了字、切出去回来就好 —— 这是 Windows 上
「窗口只剩指针焦点、丢掉键盘焦点」的典型样子，而不是页面哪里卡住了。翻遍主进程，
现在**完全没有**任何把焦点抢回来的代码（只有第二实例唤起那处）。

冷启动路径上能丢焦点的动作有三类：原生对话框（选目录、确认框）、把前台交给资源管理器
（打开文件夹／打开目录）、以及整窗或元素全屏。图片模块里，「导入目录」「整理和移动」「删除原文件夹」
「重新定位」「从哔咔下载」都会弹原生对话框，所以都符合你说的「操作之后」。

于是加了一处兜底：`electron/services/window-focus.ts`，原生对话框关掉之后、以及把前台让出去之后，
补一次窗口和页面焦点。**这是按症状和代码事实推理出来的缓解，不是抓到的复现**，
所以它有没有效，要看你还遇不遇得到。判断标准很简单：以前失灵时切出去回来才能打字，现在
弹完对话框直接就能打字，就是压住了；如果照旧，说明根因不在这里，请告诉我是哪一步之后发生的。

## 建议这样试

1. 进图片 → 漫画书架，先把某一部作品读几页，回到书架首页：应该看到「继续阅读」。
   然后点左侧任一分类：那一排应该消失；点回「全部漫画」：又回来。
2. 有分类的作品点进去，在「作品工具」那行点「打开所在文件夹」：应该打开这部作品的目录。
3. 在作品详情页点右上或工具栏的阅读，然后点阅读器标题栏的「最大化 / 还原」：应该铺满整窗、盖住顶栏；还原回到浮动位置。
4. 「从哔咔添加」→ 随便下过至少一部的账号里，「我的收藏」里那部应该带「已入库」徽标、且勾不上；
   点进去看章节，已下过的章带「已入库」。
5. 重点试第五条：连着做几次「导入目录」「整理和移动」这类弹对话框的操作，每次关掉对话框后
   立刻去搜索框打字。以前要切出去再回来的那种，现在应该直接能打。

### 改动前就红的（本轮没修）

- `scripts/verify-image-ux-ui.ts` 的 `reader-navigation`：改动前它点的是「右侧翻页」——这个名字只存在于脚本里，
  源码里从来没有这个按钮（`src/` 只剩三行没用的 `.reader-edge` 样式），所以这条检查在我动手之前就是红的。
  本轮顺手把选择器换成了现存的「后一页」，失败点因此往后挪了一格：脚本在右到左模式、停在 8／8 页时点「后一页」
  期望走到第 7 页，而最后一页的「后一页」本来就该禁用。剩下这截是**脚本期望过期**（09-30 阅读器改版时
  给底部按钮加了禁用、也重排了右到左的语义），和本轮四条改动无关。同脚本 `chapter-preview`、`compact-tools`、
  `module-logs`、`themes-layout` 四条通过 —— 其中 `compact-tools` 正好管着「作品工具那一行必须是一行」，
  说明新加的按钮没把那行挤到换行。
- `scripts/verify-image-ui.ts`：夹具给作品分配 `image-group-${i%4}`，而库里只预置两个分类
  （`electron/kinds/image/schema.ts` 只播种 `image-group-0` 待整理、`image-group-1` 喜欢的作品），
  i=2 就抛「类型不存在」。`scripts/verify-image-bulk.ts` 同样假设了 4 个预置分类。两处都是既红，没改。

### 没验的

- **第五条「输入框失灵」没有复现**，所以那处缓解有没有效也没验。
- `source-owned` 的「正在下载」分支：只在源码层面保证它和批量下载跳过重复作品的判定用同一组状态词，
