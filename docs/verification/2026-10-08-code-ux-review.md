**1. [P1] 图片详情必须校验响应所属资源**

位置：[图片详情读取](D:/8.Project/0_0_维护/抱一/src/pages/image/Detail.vue:29)、[保存操作](D:/8.Project/0_0_维护/抱一/src/pages/image/Detail.vue:36)。

在同一详情组件复用、资源 ID 从 A 切到 B 时，`load()` 没有请求轮次校验，而且两次 await 分别读取当时的 `props.id`。先请求 A、再请求 B，若 A 最后返回，会把当前页面的 `item` 改成 A，随后又按当前 B 的 ID 读取页面列表。保存、移动、删除仍以当前 `props.id` 为目标，因此显示内容和操作对象可以不一致。

复现时，先延迟 A 的读取，切到 B 并等待其正常显示，再释放 A 的响应。页面标题和路径变回相册 A，但路由仍指向 B。随后在名称输入框修改并失焦，真实 IPC 将修改保存到了 B；A 保持原名称。另一个直接加载实际 SFC 的复现还确认了 `item=A / pages=B` 的混合状态。

建议在请求开始时固定 ID 与轮次，将条目和页面读取到局部变量，校验仍属当前请求后一起赋值；保存与文件操作也要校验展示对象和目标 ID 一致。在加载未完成时暂时禁用这些操作。其他详情页可按相同标准补查，本报告没有把尚未独立复现的同类代码列为新增缺陷。

证据：[UI 数据结果](D:/8.Project/0_0_维护/抱一/output/review-20261008/ui-report.json)、[错误显示截图](D:/8.Project/0_0_维护/抱一/output/review-20261008/image-stale-detail.png)、[SFC 复现结果](D:/8.Project/0_0_维护/抱一/output/review-20261008/boundaries.json)。

**2. [P1] 影视批量提交未绑定已完成的查询范围**

位置：[批量提交检查](D:/8.Project/0_0_维护/抱一/src/components/video/VideoBulkPanel.vue:13)、[首页批量面板接入](D:/8.Project/0_0_维护/抱一/src/pages/video/Home.vue:411)。

软件和游戏已有 `queryPending` 防护；影视仅限制正在保存时重复提交，没有检查当前输入、筛选条件与已加载结果是否一致。查询期间旧卡片与选择仍保留，提交入口也仍可用。只检测保存的 `busy`，不能防止新查询等待期间误操作旧范围。

复现时先选中影片 A、B，再把搜索词改成仅匹配 B，并延迟 `video:list` 响应。页面已经处于加载状态，但“加标签”仍可点击。点击后提示“已更新 2 部作品”，A、B 均写入了测试标签。测试只延迟读取；批量更新和数据库写入使用原实现。删除与移动共用的选择入口也应一起检查，但本轮没有执行这些文件操作，不将其描述为已复现的删除事故。

建议为影视补齐查询签名与就绪状态，在防抖、等待、失败后尚未成功刷新期间锁定全选和批量提交，并提供明确的刷新出口。单纯使用 `loading` 不能覆盖输入后防抖尚未发请求的时间窗。

证据：[查询期间的界面](D:/8.Project/0_0_维护/抱一/output/review-20261008/video-pending-query.png)、[实际写入结果](D:/8.Project/0_0_维护/抱一/output/review-20261008/ui-report.json)。

**3. [P2] 项目导入把模型等待放在不可退出的模态流程中**

位置：[导入逐项等待 AI](D:/8.Project/0_0_维护/抱一/electron/ipc/project.ts:79)、[导入等待状态](D:/8.Project/0_0_维护/抱一/src/components/project/ProjectImport.vue:18)、[模态框取消行为](D:/8.Project/0_0_维护/抱一/src/components/project/ProjectDialog.vue:9)。

开启 AI 后，每个新项目完成本地登记后，还要等待 `assistant().initialize()` 完成，整个导入才返回。前端在此期间持续设为 busy，原生模态框禁止关闭和 Esc，“取消”按钮也被禁用。用户既不能停止分析，也不能回到资料库继续使用；提示文字没有逐项进度。公共 Agent 单次请求超时为 120 秒，批量导入又是逐项等待，慢模型会明显放大这一体验问题。

复现使用独立测试资料库和只监听 127.0.0.1 的 HTTP 模型服务。实际点击导入后，让模型响应暂不返回，确认取消和关闭按钮均禁用、没有停止或转后台按钮、Esc 后弹窗仍存在。释放模拟响应后，流程正常结束。没有调用用户配置的模型服务。

建议先完成本地登记并返回可用的项目列表，再把资料补全交给可停止的后台任务；如保留模态流程，至少提供停止 AI、保留已登记结果和当前处理项进度。

证据：[导入等待验证](D:/8.Project/0_0_维护/抱一/output/review-20261008/import-report.json)、[等待截图](D:/8.Project/0_0_维护/抱一/output/review-20261008/project-import-waiting.png)。

**4. [P2] 正常加载期间显示资源已失效的提示**

位置：[图片详情空状态](D:/8.Project/0_0_维护/抱一/src/pages/image/Detail.vue:46)。

切换资源时立即清空 `item`，模板对所有 `!item` 都显示“资源不可用 / 资源可能已移除，或所属类型已隐藏”。正在读取一个正常存在的相册，也会进入这条错误提示。在较慢的资料库中，这会诱导用户重新定位、扫描或误以为资料丢失。

本轮通过延迟正常 `image:get` 响应稳定复现。建议明确区分加载中、成功但不存在、读取失败三种状态；仅在读取结束并返回空值时显示不可用说明，失败时提供重试。这个修正与第一项的请求归属校验解决不同问题，应分别验收。

证据：[加载中误报截图](D:/8.Project/0_0_维护/抱一/output/review-20261008/image-loading-unavailable.png)。

**代码与体验的后续整理建议**

公共批量操作已经具备固定批次、防重复提交、部分失败和重试等基础；软件、游戏的查询签名保护也值得复用。当前问题集中在这些约束没有覆盖所有模块。建议把“当前数据属于哪个查询/资源、哪些操作可用”形成统一的小型状态约定，避免每页重新实现一套异步逻辑。

项目模块和部分图片组件将较多逻辑压在单行，包括状态切换、等待和错误处理，增加了审查与维护成本。后续修复时宜按职责拆开加载、保存与文件操作，并保留行为测试；无需为格式整理单独扩大本轮改动。

960×640 实测中，五库首页、项目详情与设置页的 document 宽度均为 960，没有页面级横向溢出。复核的深色与项目浅色截图中，主要导航和操作可见。影视批量状态的工具区占用较多纵向空间，内容区相对拥挤；“扫描本地”和“导入目录”目前又都进入 `videoImport.begin()`，可以合并入口或明确两者差别。这些属于体验优化建议，没有计入以上缺陷数量。
