# 五模块统一体验审查与验收

本轮按用户要求优先处理体验，在主会话串行实现与审查。检查单位是“导入/浏览 → 筛选/选择 → 管理/使用 → 反馈 → 返回/恢复”，不以按钮数量或历史测试数量代替流程验收。

## 直接复现的缺陷

0.14.1 隔离资料库放入 36 个软件，整理页滚动位置为 0，末行底部为 3264px，而容器底部仅 581px。根因是纵向 flex 将表格收缩，表格自身又裁切溢出；修复为滚动内容不收缩。另复现了设置进入整理后取消回跳、当前模块点击无效、普通视频出现 Hanime 专用入口。

截图复核发现清空筛选后软件搜索框仍显示旧词，补失败断言后改为单一查询状态。进一步检查了防抖窗口：用户改变查询后、结果返回前，批量提交会暂时锁定，旧响应和失败响应不能解锁新查询。

## 验证方法

- `scripts/verify-unified-ux.ts` 使用独立 Electron profile、临时软件/游戏/照片/项目文件和 SQLite 数据库，实际点击、筛选和检查 IPC 保存结果，包含 960×640 窗口及两种主题。
- 部分失败使用临时数据库触发器拒绝某一项写入；确认成功项保存、失败项名称/原因显示、只有失败项保留选择并可重试。
- 软件整理执行场景只对临时夹具创建一个链接；原软件、游戏和项目文件在测试结束时逐一确认仍存在。
- `verify-library-selection.ts` 检查可见选择、输入框 Ctrl+A、Esc、重复提交、部分失败与重试；`verify-library-query.ts` 检查防抖、旧响应、失败和恢复。
- 复用既有课程/音频/照片/项目 UI 场景与游戏封面回归。封面测试 fixture 补齐之前遗漏的 `useRoute`，不改变测试断言。
