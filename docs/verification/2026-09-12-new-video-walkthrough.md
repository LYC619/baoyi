# 新视频实测清单 · 2026-09-12

适用版本：`0.8.0-local-structure-20260912`。本轮已确认正在运行该版本。以下按钮与当前代码、最新变更说明核对过；各步骤的实际结果由本次新视频实测填写。

本轮已收到实测反馈，发现普通目录导入、NFO 强制刮削及共享目录检查等流程缺口。核对结果见[实测反馈与 18 项优化清单](D:/8.Project/0_0_维护/抱一/docs/verification/2026-09-12-new-video-feedback-audit.md)；下面的勾选项是验收目标，不能视为全部已经通过。

推荐顺序：扫描新文件 → 核对单集 → 创建合集 → 加入新集 → 下载缺集 → 收藏分组 → 重扫与观看记录。可以连续测试，最后统一反馈。

## 先记住三个入口

| 要做的事 | 使用入口 | 作用 |
| --- | --- | --- |
| 新文件还没有作品记录 | 影视 → 扫描本地 | 扫描所选目录，识别并登记作品 |
| 已有合集目录又放入视频 | 合集 → 作品内容 → 检查文件 | 发现新增文件、检查路径及本地可用状态 |
| 本地缺少来源站上的集数 | 合集 → 下载 / 补齐内容 | 对照来源目录，下载选择的缺集 |

「合集」把多个内容项放在一个作品内；「收藏分组」把若干作品放进同一个筛选分类。补集在具体作品中进行，当前没有对整个收藏分组一键补齐的入口。

## A. 识别本地新视频

建议首批选择同系列的两集；有条件再加一个无关作品，用来检查是否误合并。保持原有目录与文件名，便于观察真实识别效果。

1. 打开「影视」，点击右上方「扫描本地」。
2. 选择本轮新视频所在的目录。若是各集各一文件夹，可选它们的共同父目录，范围尽量只含本轮样本。
3. 等待完成，展开「本轮扫描结果」，记录注册、跳过、失败及待确认项。运行过程也可从顶部任务中心查看。
4. 从结果点「打开作品」。如果在影视首页找不到已登记的条目，清空搜索和筛选；Hanime 内容查看「里番」分类。

检查并记录：

- [ ] 本轮每个视频都有可追溯的登记结果，没有无提示漏项。
- [ ] 片名、原名、类型、集号和来源对应真实文件；特别留意第 0 集、番外及带副标题的单集。
- [ ] 「作品内容」中的文件可以定位；文件夹本身没有被列成可播放视频。
- [ ] 两集被识别成一个作品还是两个条目，记录实际结果。来源和目录结构会影响归并，先观察即可。
- [ ] 单集作品的简介、标签、封面与来源相符。封面记下是带标题图片还是预览图。

若预检跳转到 AI 设置，按应用提示补好配置再扫描。识别失败可先看结果原因与日志；已有记录可用「重新识别此作品」，或详情页「更多 → 重新识别 / 按里番刮削」。

## B. 创建合集

若 A 已生成正确合集，直接进入 C。若各集仍是独立条目：

1. 回到影视库，点击「创建合集」。
2. 勾选同一系列的条目，点击「下一步」。
3. 选择「创建新合集」，填写合集名称，核对自动生成的内容预览与集号。
4. 先按默认方式点击「创建合集」。需要统一文件位置时，再展开「文件整理（可选）」选择复制并核对目标目录。

检查并记录：

- [ ] 首页显示一个有效合集，原来的各集条目不会同时重复展示。
- [ ] 合集内各集的原名、简介、文件及观看状态保留；点击集名进入对应简介。
- [ ] 「作品内容」可以切换卡片和列表，数量及可播放状态一致。
- [ ] 重复集号会提示，可在预览中修正；没有自动猜号后静默合并错误内容。
- [ ] 默认组建合集后原文件位置保持原样。使用复制选项时，原文件仍保留。

当前单集标签尚未独立保存和筛选，合集右上方显示的是作品层标签。这里记录标签是否符合你的预期，作为后续改造依据。

## C. 给已有合集增加本地新集

按实际文件位置选择一条路线：

| 新一集的位置 | 操作 |
| --- | --- |
| 已放进已有合集的受管理目录 | 进入合集 → 作品内容 → 检查文件 |
| 仍在另一个独立文件夹 | 扫描该文件夹；回到首页点创建合集，同时勾选新条目与目标合集 → 下一步 → 加入已有合集 → 选择目标 → 加入合集 |

检查并记录：

- [ ] 新一集出现，原有集数和观看记录保留。
- [ ] 再点一次「检查文件」，同一个视频不会新增第二份记录；页面显示检查结果。
- [ ] 新文件的集号与归属正确；来源不足时，把缺少的资料记下来。

「检查文件」侧重本地发现和路径核对；缺少的来源、简介等资料，还需识别或补齐资料。逻辑合集的文件可以分布在不同目录，新增文件放在哪里会决定采用哪条路线。

## D. 补齐站点上的缺集

1. 在作品内点「下载 / 补齐内容」。已有来源时读取来源内容；需要时填对应 Hanime 页面链接并点「解析链接」。
2. 先核对列出的集号、原名、来源内容数量及「本地已有」数量。
3. 核对保存位置是当前作品/合集目录。若有目录更名，面板应明确列出当前目录与本次使用的目录。
4. 点「只选缺失」，第一轮选一集缺集即可；选择画质，保留「登记到影视库」，点击「下载所选」。
5. 从顶部任务中心查看完成情况，再「打开作品」。

检查并记录：

- [ ] 本地已有的集数能被认出，即使本地文件名和网站标题不同；默认选择不会把它们重复下载。
- [ ] 第 0 集和番外按来源依据显示，没有把播放列表位置当成集号。
- [ ] 新文件名包含原名、集号及实际画质；既有文件名与观看记录保留。
- [ ] 下载完成后归入当前合集，没有多出一个同内容作品。
- [ ] 再次解析时，新下的集数变成「本地已有」。
- [ ] 若视频已保存而资料或入库失败，任务中心提供对应的「补齐资料」或「仅重试入库」；这些操作复用已下载文件。

当前下载入口支持 Hanime 来源页。收藏分组本身不能代替来源系列目录。若「本地已有」判断不对，先记录对应文件、集号与来源，再决定是否继续下载该项。

## E. 填写收藏分组

1. 打开一个作品或合集，点击「编辑资料」。
2. 切到「文件与资料」，在「收藏分组」输入名称，例如「本轮实测」。
3. 离开输入框完成保存，再点「完成编辑」。
4. 给另一个作品填写同名分组，点击「查看分组」或左栏同名分组。

检查并记录：

- [ ] 同名分组下可看到对应作品，重开应用后仍保留。
- [ ] 分组不会把两个不同作品合成一个合集，也不会移动文件。

## F. 重扫、简介、笔记与观看状态

- [ ] 重扫本轮相同目录后，同一作品、同一视频不重复出现；已组建的合集保持归属。
- [ ] 点击不同集名，或在「剧情简介」的「查看范围」切换单集，看到对应简介和原文。
- [ ] 在「个人笔记」选择一集，编辑保存一条测试笔记；切换其他集，内容不串集。
- [ ] 标记一集「看过」后，页面仍正常，合集已看数量更新，其他集状态不受影响。
- [ ] 从顶部任务中心打开影视作品，再点「返回影视库」，返回影视页并保留相关筛选。

## G. 按需补测的功能

| 功能 | 操作及检查点 |
| --- | --- |
| 合集更名 | 有受管理目录时：更多 → 修改合集名称。核对名称与目录变更预览；执行后检查作品位置、文件可用性与重启后的记录 |
| 整理记录与回退 | 创建合集后查看整理记录；需要撤销本次测试合集时用「回退本次操作」，查看逐项结果与冲突提示 |
| 版本管理 | 同一内容有多个已关联文件时，在作品内容切换版本并设置默认版本，核对播放目标 |
| 从链接新增 | 影视 → 从链接添加 → 解析 Hanime 链接；核对默认影视库、作品子目录、画质与登记方式 |
| 资源包导入 | 有抱一资源包时，影视 → 导入，选择其目录；核对标题、单集、来源和文件路径，重复导入不产生重复项 |
| 待处理项 | 在影视库查看待补海报、文件失联、资料待补齐、下载待处理及归属待确认条目，核对实际问题与入口是否匹配 |
| 资料备份 | 设置的数据备份区导出 JSON；它备份资料、观看及任务记录，不包含视频文件或 API 配置。恢复会替换当前资料库并重启，另作专项测试 |

## 本轮先收集的设计建议

推荐继续采用「合集组织、单集独立资料、文件关联单集」的结构：

- 每集按来源编号保持独立身份，拥有自己的标题、简介、标签、封面和观看记录。同一集的不同画质作为文件版本关联。
- 影视首页默认显示合集卡片，支持展开各集；合集内点击单集进入其资料。按标签筛选时，展示实际命中的集数和单集。
- 合集可以显示汇总标签，但应说明哪些集命中，避免把某一集的标签当成整部合集共有的属性。
- 宣传封面与视频预览图分开保存；有合适的带标题封面时优先展示，也应允许手动选图。单集独立登记本身不能保证取到不同的图片。

当前已支持单集简介、封面、笔记、观看记录及合集内卡片/列表；尚未支持单集标签、按单集标签筛选及首页原地展开合集。这些属于本轮反馈后的设计项。
