# 可选视频解析服务：预留接口

2026-10-02 决定：抱一以个人本地资源管理为主，在线浏览和下载是辅助功能。用户目前没有解析 API 或服务器，先保留扩展接口。没有安装 yt-dlp、FFmpeg、Python、Docker，也没有启用外部解析或新增设置入口。

当前交付只有 [主进程类型契约](../electron/kinds/video/discovery/resolver-contract.ts) 和本说明。它不是已实现的下载功能；现有网页适配限制仍然存在。所有新声明均为 TypeScript 类型，不增加运行时逻辑或依赖。

## 接口语义

| 契约 | 用途 |
| --- | --- |
| `VideoResolverConfig` | 未配置等同于 `{ enabled: false }`。启用时记录适配器编号、服务基础地址、可选凭据引用。当前不落库。 |
| `VideoResolverContext` | 主进程临时凭据和取消信号；不交给网页或渲染进程。 |
| `resolve` | 输入具体视频页面，返回标题、封面、站点稳定 ID 和格式列表。仅提取资料，不下载视频。 |
| `prepare` | 用户点击保存、选择格式后请求准备完整文件。返回文件，或远端任务编号，或规范化错误。 |
| `poll` | 可选。异步服务查询远端任务，继续返回 pending/ready/failed。轮询间隔由客户端设上下限。 |
| `cancel` | 可选。服务支持才实现；本地停止等待不能宣称远端任务已经取消。 |
| `VideoResolverFile` | 服务准备好的完整视频文件、扩展名、可选过期时间及临时请求头。不是 HLS/DASH 清单或单独音轨。 |

这是抱一内部适配契约，不是假定所有服务都遵循的 HTTP 格式。实际服务的端点、鉴权、响应结构由各自适配器转换。第一版有真实服务时只接一个适配器，不建立通用插件系统。

## 与现有功能的接入顺序

1. 在主进程读取显式启用的配置；没有配置时不发请求、不轮询、不查找或安装外部程序。只有用户操作时，才把选定视频 URL 发给已配置服务。
2. `resolve` 结果必须经过运行时校验，再映射到 `DiscoveryEntry`：以站点与视频 ID 构造稳定身份，将标题、封面、简介、原页面写入海报墙。格式 ID 不冒充 `downloads` URL；凭据、签名文件地址不放进收藏身份。
3. 用户保存时创建可恢复的本地任务，再调用 `prepare`。远端任务和本地传输是两个阶段；当前 `DiscoveryWorkflow` 只接受完整文件，尚需增加这层协调后才能实际启用。
4. `ready` 后通过已有传输和登记逻辑保存。现有目录只支持部分完整视频扩展名，文件必须经过 HTTP 状态、容器和完整性检查。不能把 `.m4s`、播放清单或网页改名成 `.mp4`。服务文件 URL 无扩展名时可以单独提供 extension；现有内播校验更严格，需要另行适配。
5. 文件过期时重新准备；重试本地登记时优先复用已完成文件。保存任务的站点身份、格式 ID、服务配置引用及必要远端任务编号，不保存 API 密钥、Cookie 或长期复用短期签名 URL。
6. 服务失败或未配置不影响已有目录、个人标记和本地文件。页面应区分无法解析、需要登录、服务不可达、文件过期；不能暗示任意网站或免登录高画质均可用。

远端基础地址必须校验 HTTP(S)、拒绝 URL 内嵌用户名密码。真实凭据使用系统安全存储，普通配置只保留引用；错误及日志脱敏。服务鉴权只发送到指定服务，不随文件地址或跨站重定向泄露。`requestHeaders` 也需由适配器验证作用域，不能直接信任远端返回的任意请求头。这些是未来实现要求，类型声明本身不提供运行时安全保证。

远端下载后再传到本机，会占用服务器临时空间和流量。若服务放在同一台电脑，整体资源消耗仍然存在，只有抱一安装包变小。因此不把自建服务作为普通用户的默认前置条件。

## 候选服务核验

以下是 2026-10-02 阅读上游文档和 GitHub 仓库元数据的结果，未部署、未验证真实站点下载。README 的宣传不能代替实测。

- [Vasysik/yt-dlp-host](https://github.com/Vasysik/yt-dlp-host)：未归档，最后推送时间显示为 2026-09-23。[API 文档](https://github.com/Vasysik/yt-dlp-host/blob/main/docs/api.md) 列出 `/get_info`、`/get_video`、`/status/<task_id>` 和 `/files/<path>`。具备远端文件取回接口，可作为有服务后的优先考察对象。文档中的任务接口没有列出取消端点，不能承诺远端取消。
- [fvadicamo/yt-dlp-api](https://github.com/fvadicamo/yt-dlp-api)：未归档，最后推送时间显示为 2026-08-10。README 提供元数据、格式、下载和任务查询；返回服务器文件路径不等于桌面端可下载的 URL，实际接入前需核对文件传输方案。
- [zasdevs/yt-dlp-api-server](https://github.com/zasdevs/yt-dlp-api-server)：仓库元数据显示最后推送为 2022-08-19，本次 `main/README.md` 返回 404，不作为首选。
- [cobalt](https://github.com/imputnet/cobalt/tree/main/api)：文档明确没有公开托管 API，需要自建或取得实例访问权限；不能当成默认免费接口。当前列表包含 B 站，未列 Pornhub。

RapidAPI、Apify 等托管服务可在确定具体接口及账户后另做适配；本轮不订阅、不写入预置密钥、不选择不明公共解析站。Python 的 `import yt_dlp` 不适用于直接嵌入当前 Electron/TypeScript 主程序，也不能消除 FFmpeg 等组件的体积。

## 有服务后的验收要求

拿到真实 API 地址和文档后，先验证一个具体视频的资料、音画完整的文件交付和鉴权，再增加该适配器、配置 UI 和 IPC。验证应覆盖：无配置零网络请求、解析不下载、远端失败、地址过期、跨站凭据隔离、取消边界、重启恢复、本地字节一致和入库。站点覆盖及免登录能力以实测结果标注；首页列表接入单独评估，不由单视频解析能力推断。
